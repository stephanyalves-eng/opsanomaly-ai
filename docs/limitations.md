# Known limitations and operational risk — audit v2

## Scientific and statistical limits

- Data is original, easy synthetic point-spike injection, not an independently verified anomaly benchmark or physically validated industrial process. No real failure detection, diagnosis, safety, causality or RUL capability is established. Near-perfect ranking and zero observed false alarms are simulation outcomes, not performance promises.
- Only seeds 42/43/44 and one fixed spike protocol were compared. Three runs are insufficient for reliable uncertainty intervals, significance claims or declaring a winner. Reported seed population standard deviation is not a confidence interval. No contextual drift, maintenance episodes, attacks, correlated asset faults, realistic missingness or sustained failures were benchmarked.
- Train/calibration contain injected positives; they are not filtered with labels. This is not held-out leakage, but contaminated high quantiles can suppress recall. Default 2% alert budget is below approximately 4% injection frequency. Thresholds were not optimized for F1, false-alarm cost or labeled performance. With ties and phase changes, observed alert rates may differ materially from the chosen budget.
- Threshold choice, window size, seeds and generator protocol are configurable. Automated code does not tune using test labels; human selection after viewing test results can still contaminate the experiment. UI results are explicitly exploratory. Freeze settings outside the holdout and use a new external test before making confirmatory claims. `test_labels_used_for_tuning: false` describes the executable pipeline, not an attestation about a caller's prior experiments.
- Point precision/recall/F1 are not event metrics. No point adjustment, anomaly-window expansion or favorable test-based threshold optimization is applied. False alarms / 1,000 uses FP / all observations, not FP / negatives. AP and trapezoidal PR area are reported separately. Single-class labels make both PR summaries null; undefined precision/recall/F1 use zero with explicit denominator flags. Tiny endpoint roundoff is bounded to [0,1] within 1e-12; larger invalid results fail.
- Metrics require complete binary labels. Labels are assumed accurate; no annotation-quality audit, delayed-label handling or event taxonomy is provided. Unlabeled data supports distributions and alert rates only, never estimated precision, recall, F1, PR-AUC or false-alarm claims.

## Temporal and model assumptions

- Pooled models require comparable sensor units and asset distributions. Shared UTC split cutoffs avoid cross-asset future leakage, but this evaluates known assets in later periods, not generalization to unseen equipment. Every asset must have coverage in all three periods, or the split is rejected. Ratios apply to distinct timestamps; irregular assets can have unequal row fractions. New assets are rejected at inference.
- Quantile cutoffs use the full dataset's timestamp availability to define retrospective benchmark periods, never sensor values or labels. A real deployment should predeclare wall-clock cutoffs and latency/availability assumptions. Synchronized UTC timestamps are assumed to reflect information availability; incorrect clocks, delayed/backfilled sensor arrival and cross-asset dependencies are not modeled. No label horizon or feature windows cross partition boundaries; RUL/event targets would require separate purging/gaps.
- Frozen MAD may miss regime changes. Rolling MAD uses a 31-observation window, not a fixed elapsed-time window: irregular sampling changes its time horizon. It can adapt away sustained anomalies, be contaminated by consecutive anomalies, and become unstable with short/constant histories. Zero local MAD uses training scale, whose constant-feature fallback is one raw unit and therefore unit-dependent. No probabilistic calibration, drift alert or autonomous retraining is provided.
- Rolling scoring appends prior test sensor values after scoring, including previously alerted rows; labels never update state. This online reference differs from the frozen forest and MAD models. Their equal nominal alert budgets do not imply equal realized false-alarm budgets or detection costs. All methods share training-only imputation; missingness itself is not modeled as an anomaly and can hide faults or contribute imputed deviations.
- Predictions replay the supplied batch from immutable calibration-end history. Multiple separate calls are not continuous streaming state; later chunks without all intervening observations use stale context. Replay the complete post-calibration sequence. A missing interval does not automatically clear history. No persistent stream/checkpoint API exists.
- Feature evidence describes deviations. It is neither causal nor exact Isolation Forest attribution. The forest contextual MAD reference can disagree with what the forest learned; do not present it as SHAP, feature importance, fault isolation or a validated explanation. Multi-feature interactions may drive forest alerts without a dominant univariate deviation.

## Software, security and reproducibility

- CSV only, up to 100 MB, 1,000,000 rows and 64 sensors. Explicit timezone offsets and increasing times per asset required. Missing values use training medians; entirely missing training sensors are rejected. +/-1e12 is a numerical guard, not an engineering operating limit. Resource caps are input bounds, not a performance guarantee; exact rolling medians cost roughly O(rows * window * sensors), with windows limited to 3..1000.
- Legacy artifact schema v1 is unsupported; retrain. Dataset/model pairing and partition hashes detect mismatches, not malicious coordinated edits. Joblib/pickle can execute code: load only trusted local artifacts. Models may contain sensor/history information and must not be published from private data.
- The local Gradio UI is not hardened multi-user infrastructure. No auth, encryption at rest, SLA or secure remote serving is supplied. Loopback only; no public share links. Temp export and Gradio cache cleanup can leave original OS temp files. Local users must handle private-data retention and shared-device privacy. The audit focused on ML validity, not comprehensive hostile CSV/serving penetration testing.
- Exact version pins are not wheel-content hashes; supply-chain authenticity is a separate risk. Existing dependency audit is point-in-time evidence and was not rerun for this code-only change. No dependency versions were added or changed. Upstream Matplotlib/pyparsing deprecation warnings remain. Floating-point output and runtime can vary across systems; timings are single warm batch measurements, not SLAs.
- Windows/Python 3.12 is locally verified. Python 3.11 and Linux are CI targets; hosted CI has not run. Python 3.13+ is excluded pending compatibility work. No hosted publication, purchase, external dataset/model download or real-data validation was performed during this audit.

## Expanded stress evidence (2026-11-21)

The earlier audit's untested-scenario statements describe its original spike-only scope. A subsequent, separate fixed synthetic suite now covers finite gradual drift, sustained shifts, plausible stuck values, nuisance missingness, total outages and spikes with random missingness. It confirms severe rolling adaptation and missingness/stuck-sensor blind spots; see stress-evaluation.md. These are designed injections with subjective normal/anomaly label policies, not real maintenance failures or an external anomaly benchmark. Homogeneous assets, abrupt recovery, limited severities, only three seeds and no clock/arrival dynamics remain major limits. Clean calibration differs from the previous contaminated benchmark; cross-suite score improvements would be misleading. The inspected stress results are development evidence, not an untouched future validation set for any subsequent model changes.

## Raw quality rules and new-seed validation (2026-11-21)

QualityMonitor is now a separate raw-value review channel, not a repair to numeric ML performance. It uses fixed 8-repeat/3-missing rules, training-only variability/cadence and tolerance 1e-8. Three new seeds and 11 cases expose a fundamental ambiguity: legitimate plateaus and injected stuck sensors with identical readings produce identical review flags. Stable processes can therefore trigger review without any sensor defect. Training constants are not assessable for repetition. Absolute tolerance, run lengths and cadence need domain validation; gaps reset state and count-based delay is not fixed elapsed time. Completely absent records are not NaN cells: no heartbeat/resampling timer detects silent telemetry loss. Raw data must reach the monitor before numeric imputation. No persistent stream state, fault diagnosis or overall ML accuracy gain is claimed. See quality-evaluation.md for all results, controls, API constraints and remaining limits.

## External NAB subset (2026-11-21)

The project now includes an initial real-data experiment, superseding the earlier synthetic-only scope for current development evidence. Two publisher-released series are evaluated with poor fixed-threshold results; one preselected machine series is rejected for 12 conflicting timestamps. This is a small convenience subset, not an industrial validation or official NAB benchmark score. Publisher interval labels are mapped to point membership without point adjustment; physical source clock/units and detailed provenance remain unverified. Root MIT declaration and metadata were checked/preserved; no separate dataset license or rights-chain warranty was invented. Raw files remain ignored and local. Source-quality failures, training contamination, boundary clipping and already-inspected holdouts are explicit. See nab_dataset_card.md and nab-evaluation.md for all evidence and remaining work.
